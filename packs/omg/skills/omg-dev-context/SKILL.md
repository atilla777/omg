# Shared development context

Use this contract when an `omg-development` step needs its source or prepared workspace. The assigned step's own skill still determines what work to do, which predecessors to inspect, and what artifact to write. Do not create a workspace from any step other than `prepare`.

1. Claim only the assigned step. Resolve its prefix to exactly one project rig using `gc rig list --json`; the city working directory is not the rig. Use `bd -C <rig-path>` for **every** Beads operation. Read the claimed step and its `gc.root_bead_id`, then read that root and its `gc.var.source_id`. Require the step and its required predecessors to belong to the same root, and the root to have `gc.formula_name=omg-development`. The original source bead must have that ID and type `omg-development`; never substitute a step, control bead or input convoy ID for it. On missing or conflicting identity, record the reason and leave the step open.
2. For steps after `prepare`, read the closed prepare bead for this root and the worktree/branch/context it recorded. Require `omg.workspace.path` and `omg.workspace.source_id` on the root to match prepare and the original source, and verify that the absolute worktree belongs to the expected task branch; do not derive its path from the current step ID. When publishing, also use `gc worktree verify` with prepare's recorded provisioning identity and base SHA. Do not replace mismatched metadata or adopt another worktree.
3. If the root has `omg.workspace.artifacts_root`, require `omg.workspace.source_id` and `omg.workspace.path` and verify that the **recorded absolute** artifacts directory is exactly `<verified-worktree>/.omg/tasks/<source-id>/artifacts/`. Reject `..`, symlinks and path escapes at every component. Use only this recorded directory; do not choose a directory by searching for filenames. If the root lacks `omg.workspace.artifacts_root`, this is an already-started workflow: use the prepared `docs/tasks/<source-id>/` path recorded by its prepare step inside its worktree, without silently switching to `.omg/tasks/`. Presence of `.omg/tasks/` alone does **not** identify the review schema: a previously started workflow may already use it.
4. Before consuming an artifact, read the exact path recorded by its producing bead; check the bead's source/root and any identities present in the artifact against the claimed step. For review artifacts also apply `omg-dev-review-attempt`. Keep operational artifacts in the selected prepared directory; write exact output paths back to the owning bead and read them back. On failure or missing evidence leave the step open with a precise reason. The step's own skill governs closing and any additional publication protocol.
