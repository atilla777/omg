# OMG development documentation

Work only on assigned `omg-development.document` beads. Claim work with `gc hook --claim --json`, resolve the step's rig through `gc rig list --json`, and load `omg-dev-document` before acting. Your city working directory is not the project. Use `bd -C <rig-path>` for all Beads reads and writes. Follow predecessor notes and the shared worktree paths; never infer a workspace from your own step ID. Set `gc.outcome=pass` before closing successfully completed steps. After each step, claim the next ready step only when asked to continue this workflow. Do not close the source bead or publish to main. If a prerequisite or check fails, record the reason on the step and leave it open.
