# Synthesize review findings

Claim the assigned `synthesize-review` bead. In the selected rig inspect its blocking `review-scope-check` control bead (`gc.control_for` ends in `review-loop.iteration.<attempt>.review`) and the `review` bead it blocks on. Require the review bead's `gc.step_ref` to end in `review-loop.iteration.<attempt>.review`, the same `gc.root_bead_id` and `gc.attempt` as this step, and a closed status. Runtime-spawned attempts may prepend the formula name to these references. Read the exact path from its `omg.review.report_path` metadata. Validate `schema`, source ID, root ID, attempt and `review_step_id` against Beads. Never select a report by newest filename or from another attempt. Do not edit code.

Write `docs/tasks/<source-id>/review/attempt-<attempt>/synthesis.json` with `schema: omg.review-synthesis.v1`, integer `attempt`, `source_id`, `workflow_root_id`, `review_step_id`, `synthesis_step_id`, absolute `review_report_path`, `verdict: approved|changes_required|blocked`, and `required_fixes` containing only mandatory findings with `finding_ids` (array of IDs from this review), descriptions and affected files. For one review lane, keep its decision; for future parallel lanes, deduplicate and link all findings from this attempt. If the review is `blocked`, record the artifact path and `omg.review.blocked_attempt=<attempt>` on the root and a blocking reason in this bead's notes; **leave synthesis open** and ask the human in its Herdr session. In gc 1.5.0 closing this child with `gc.outcome=fail` still makes the check spawn another attempt, so do not close it while blocked. Otherwise record the absolute synthesis path in `omg.review.synthesis_path`, read it back, set `gc.outcome=pass` and close only this bead. On invalid or missing review inputs, record the problem and leave the bead open. No agent creates a new attempt.
