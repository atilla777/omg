# Review one attempt

Claim the assigned review bead; require positive `gc.attempt`, `gc.step_ref` ending in `review-loop.iteration.<attempt>.review`, and the root's `gc.var.source_id`. Read closed prepare/plan/implement/document beads for the same root and their recorded context and evidence. Inspect code, tests and documentation against the source criteria without editing. Use `bd -C <rig-path>` for all Beads operations.

Read this attempt's workflow children before writing: if it has a `synthesize-review` bead, follow the **existing** v1 review contract (synthesis will supply `required_fixes`); otherwise follow v2. Do not infer the schema from the presence of workspace metadata: earlier workflows may already use `.omg/tasks/`. For roots with `omg.workspace.artifacts_root`, require `omg.workspace.source_id` and `omg.workspace.path` to match the source and verified worktree, and the directory to be `.omg/tasks/<source-id>/artifacts/` within it, without `..` or symlink escape. Create `review/attempt-<gc.attempt>/` inside that directory and write `review.json` and a separate human-readable `review.md` **in the same attempt directory**. Older roots without that metadata use `docs/tasks/<source-id>/review/attempt-<attempt>/review.json` in their prepared worktree without requiring a new Markdown report. Write JSON with `schema: omg.review.v2` for a direct review → fix attempt (or `omg.review.v1` for a synthesis attempt), integer `attempt`, `source_id`, `workflow_root_id`, `review_step_id`, `verdict: approved|changes_required|blocked`, and `findings` (unique stable per-attempt IDs, severity, rig-relative affected files and actionable descriptions). For v2 also include `required_fixes`: actionable items with nonempty `finding_ids` referencing findings, descriptions and rig-relative affected files; `changes_required` needs at least one, `approved` needs neither findings nor required fixes. For roots with workspace metadata include `markdown_report_path` (worktree-relative path of `review.md`) and `reviewed_files`: inventory `git -C <worktree> ls-files -m -o -d --exclude-standard -z`, record exactly these rig-relative paths with SHA-256 of each regular file (null for deletions), reject symlinks and unrelated changes. The map is a snapshot of **everything** reviewed for publication. The Markdown file explains the verdict and findings for this source/root/attempt without duplicating large prose in the bead. Record the exact JSON path as bead `omg.review.report_path` and, when written, the Markdown path as `omg.review.markdown_path`. Read files and metadata back. On `blocked`, record the reason and question on the review bead, leave it open in Herdr until the human answers: closing it would let gc 1.5.0 advance the iteration. Otherwise set `gc.outcome=pass` and close only this bead. If review or inputs are incomplete, leave it open with notes. For an already-started v1 synthesis workflow, keep the prior behavior: close the review with its v1 verdict and let `omg-dev-synthesize` handle `blocked`.
