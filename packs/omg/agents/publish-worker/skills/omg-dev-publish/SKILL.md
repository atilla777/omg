# Publish and close one source

Only claim `omg-development.publish` in the selected rig. Use `bd -C <rig-path>` for Beads, not the city directory. Resolve the source from root `gc.var.source_id`, and the worktree from `omg.workspace.path`; verify `task/<source-id>` branch, the matching source type and `gc worktree verify` with prepare's recorded identity/base SHA. Never publish from a different worktree. The source must be open, or already closed with the **same verified commit** on retry.

1. Follow publish's blocker to the closed, passing `review-loop` (for old workflows, through its closed `finalize` blocker). Read attempt beads by this root's `gc.root_bead_id`, `gc.attempt` and `gc.step_ref`; require latest review `approved`, its fix `no_op`, and the passing check outcome. Read exact report/fix paths from those beads' metadata, validate schemas, IDs, attempt and the v2 fix's `review_step_id` and worktree-relative `review_report_path`; never choose the latest file by filename. For an already-started workflow with a `synthesize-review` bead in the latest attempt, instead require its closed v1 synthesis `approved`, the v1 fix linked to that synthesis and the v1 review report with matching IDs, verdict and report path. Do not treat a missing synthesis on a v1 review as a direct-review workflow. For new runs require the root's absolute `omg.workspace.artifacts_root` and `omg.workspace.source_id` to match the verified worktree and source ID: `.omg/tasks/<source-id>/artifacts/` within that worktree, without `..` or symlink escape. Put `publish-manifest.json` and `publication-report.json` in that recorded directory; they remain local and ignored by Git. Stop open on missing or mismatched metadata. Older runs without this metadata use the `omg.publish.manifest_path` recorded by finalize and the adjacent legacy report path.
2. Read the prepared base SHA and inspect the task branch HEAD **before choosing the path below**. If HEAD equals base, use the fresh-publish path: check clean index and inventory changed files with `git -C <worktree> ls-files -m -o -d --exclude-standard -z` (include deletions). Check `git -C <worktree> status --short` and review all changes. Reject symlinks, unrelated paths, files inside `.omg/` and unexpected operational `docs/tasks/` for new runs. For new runs require the approved review report's `reviewed_files` to map **exactly** these rig-relative paths to current SHA-256 (null for deletions); compare every hash immediately before staging. For an older run exclude only its own recorded `publish-manifest.json` from this inventory and compare all other paths with its `files` map. For new runs write/read a local JSON manifest with `schema: omg.publish-manifest.v1`, `source_id`, `workflow_root_id`, `review_loop_id`, `base_sha`, and the verified `files` map; record its path as root `omg.publish.manifest_path`. Check local `main` and `git ls-remote origin refs/heads/main` equal base. If either moved, stop for explicit reconciliation and another review: do not rebase, merge, force push or silently adopt a new base. Stage **only** manifest-listed source paths (`git -C <worktree> add -A -- <each verified path>`), plus the already-reviewed legacy manifest on older runs (the new manifest is ignored). Read staged paths and compare them exactly to these allowed paths; run `git -C <worktree> diff --cached --check`, check staged blob hashes (null for deletions), then commit **once** on `task/<source-id>`.
3. If HEAD differs from base, use the retry path **without re-running the pre-commit inventory check**: require `HEAD^` equals base, a clean index and worktree (except the previously written local legacy `publication-report.json`), and the already-recorded manifest with source/root/base/review IDs and hashes matching the committed tree changes (`git diff --name-only HEAD^ HEAD` and committed blob hashes). For old runs the one committed legacy manifest is the only extra path; verify its committed contents match the recorded manifest. Require other hashes also equal the approved review snapshot for new runs. Reject any additional commits or changes. For either path read remote main: if it already contains the verified task commit, reuse that SHA without another push or commit; otherwise push only when remote main still equals base, using `git -C <worktree> push origin HEAD:refs/heads/main` **without force**. If remote advanced without containing the task commit, stop. Do not use `gh` or open a PR: this method publishes directly to main.
4. Fetch remote main and require the task commit to be its ancestor. Fast-forward the rig's local `main` to that fetched ref (never reset; on a conflicting local main leave this step and source open). Verify `git ls-remote origin refs/heads/main` equals local `main`, and that it contains the task commit. Write local `publication-report.json` with `schema: omg.publication.v1`, source/root IDs, task commit, verified remote/local SHA, manifest path and `status: published`; read it back. Record `omg.publish.commit`, `omg.publish.report_path`, `omg.publish.status=published` on the root **and** this step. Verify metadata and remote/local main again. Only then record the same commit/report and `gc.outcome=pass` on the **original source bead**, close it and read its closed state back. Finally set `gc.outcome=pass` and close this publish bead. On any error leave it open with a precise reason; if push succeeded but later confirmation failed, keep source open and resume verification on retry. Do not close the epic, convoy, loop or another source.
