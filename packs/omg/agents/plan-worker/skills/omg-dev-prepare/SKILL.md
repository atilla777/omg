# Prepare the development workspace

1. Claim the assigned step with `gc hook --claim --json`; resolve its prefix to exactly one project rig using `gc rig list --json`. Read the step and its `gc.root_bead_id` with `bd -C <rig-path> show <id> --json`. Require `gc.step_id = omg-development.prepare`, `gc.formula_name = omg-development` on the root, and `gc.var.source_id` on the root equal to the source ID in the step. Read the source with `bd -C <rig-path> show <source-id> --json`; require its type `omg-development`, its open state, and a requirements reference (if provided) resolving inside the rig. If ambiguous, leave the step open with a note explaining why.
2. Resolve the Git top-level of the selected rig, not the city. Require a committed `main` and a clean main worktree (`git status --porcelain`), without modifying the rig's Beads files. Verify the source ID is a safe single path component (`^[A-Za-z0-9][A-Za-z0-9._-]*$`). The branch is `task/<source-id>`; the per-rig root is `<rig-parent>/.omg-worktrees/<rig-directory-name>`, and the path is `<root>/<source-id>` (absolute, direct child). Create only the root directory when needed. Use Gas City's transactional owner, not raw `git worktree add`: `gc worktree ensure --repo <rig-path> --root <root> --path <path> --base main --branch task/<source-id> --bead <source-id> --store-ref rig:<rig-name> --creator omg-development --owner omg.plan-worker --generation <workflow-root-id> --json`. First use `--dry-run`, then run ensure and capture its JSON including provenance and `base_sha`. If a workspace or branch is present with incompatible provenance, stop; never reset or overwrite it. Verify the resulting worktree with `gc worktree verify` using exactly the same arguments and the returned `--base-sha`. If an existing path was created by an older method without provenance, report it for reconciliation instead of adopting it silently. The artifact directory is `docs/tasks/<source-id>/` **inside that worktree**.
3. Create `docs/tasks/<source-id>/` in the verified worktree. Write `context.md` with selected rig and source ID, source title/type, requirements reference, workflow root ID, returned base SHA, branch, absolute worktree path, artifact directory, ensure provenance and step IDs known so far. Record branch, worktree, `context.md` path and ensure identity in the prepare bead notes (`--append-notes` when notes already exist) and the root metadata `omg.workspace.path` and `omg.workspace.source_id` using `bd -C <rig-path> update`. Read the file and metadata back; set `gc.outcome=pass` and close **only** the prepare step after both agree. If any operation fails, note what was created and keep the step open; do not claim preparation succeeded.
