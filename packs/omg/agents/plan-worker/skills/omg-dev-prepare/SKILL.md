# Prepare the development workspace

1. Claim the assigned step with `gc hook --claim --json`; resolve its prefix to exactly one project rig using `gc rig list --json`. Read the step and its `gc.root_bead_id` with `bd -C <rig-path> show <id> --json`. Require `gc.step_id = omg-development.prepare`, `gc.formula_name = omg-development` on the root, and `gc.var.source_id` on the root equal to the source ID in the step. Read the source with `bd -C <rig-path> show <source-id> --json`; require its type `omg-development`, its open state, and a requirements reference (if provided) resolving inside the rig. If ambiguous, leave the step open with a note explaining why.
2. Resolve the Git top-level of the selected rig, not the city. Require an accessible `origin/main`, a committed local `main` and a clean main worktree (`git status --porcelain`), without modifying rig Beads files. Fetch `origin/main` and check local `main`: if behind and clean, fast-forward it before preparing a dependent subtask; if diverged, stop for reconciliation. Verify the source ID is a safe single path component (`^[A-Za-z0-9][A-Za-z0-9._-]*$`). The branch is `task/<source-id>`; the per-rig root is `<rig-parent>/.omg-worktrees/<rig-directory-name>`, and the path is `<root>/<source-id>` (absolute, direct child). Create only the root directory when needed. Use Gas City's transactional owner, not raw `git worktree add`: `gc worktree ensure --repo <rig-path> --root <root> --path <path> --base main --branch task/<source-id> --bead <source-id> --store-ref rig:<rig-name> --creator omg-development --owner omg.plan-worker --generation <workflow-root-id> --json`. First use `--dry-run`, then run ensure and capture its JSON including provenance and `base_sha`. Verify the result with `gc worktree verify` using exactly the same arguments and the returned `--base-sha`. On incompatible provenance, stop; never reset or silently adopt an older worktree.
3. Resolve the pack's `assets/scripts/task_workspace.py` from the root's `gc.formula_source`. Run `python3 <resolver> --worktree <worktree> --task <source-id> --mkdir artifacts-root` to create the task's operational workspace. Inspect `git -C <rig-path> ls-files .omg`: if any `.omg/tasks/` file is already tracked, stop for reconciliation; do not overwrite it. To ignore runtime artifacts in **this rig**, use an existing Git ignore rule, or append `/.omg/` to the repository's shared `git rev-parse --git-path info/exclude` only when `.omg/` has no tracked files; if it also contains tracked configuration append only `/.omg/tasks/`. Preserve existing entries, verify `git -C <worktree> check-ignore -q .omg/tasks/<source-id>/artifacts/context.md`. Do not stage this local workspace or change the rig's tracked `.gitignore` implicitly.
4. Resolve `context.md` through `python3 <resolver> --worktree <worktree> --task <source-id> artifact context.md`. Write rig name, source ID/title/type, rig-relative requirements reference, root ID, base SHA, branch, worktree provisioning identity and artifact root `.omg/tasks/<source-id>/artifacts/`. Record the absolute worktree and context paths and branch in prepare notes (`--append-notes` when necessary), and `omg.workspace.path`, `omg.workspace.source_id`, `omg.workspace.artifacts_root` (absolute resolver output) on the root with `bd -C <rig-path> update`. Read the file and metadata back; set `gc.outcome=pass` and close only prepare when they agree. On failure record what was created and leave the step open.
