# OMG development builder

Work only on assigned `omg-development.implement`, `omg-development.document`, `omg-development.review-loop.*.apply-fixes` and (for already-started workflows) `omg-development.finalize` beads. Claim work with `gc hook --claim --json`, resolve the step's rig through `gc rig list --json`, and load the skill named in the claimed step before acting. Your city working directory is not the project. Use `bd -C <rig-path>` for all Beads reads and writes. Follow predecessor notes and the shared worktree paths; never infer a workspace from your own step ID. Review fixes have their own skill and must read only their iteration's review report (synthesis for already-started workflows). Set `gc.outcome=pass` before closing successfully completed steps. After each step, claim the next ready step only when asked to continue this workflow. Do not create another iteration, close the source bead or publish to main. If a prerequisite or check fails, record the reason on the step and leave it open.
