# OMG — Oh My Gas City

OMG — проект набора настроек и Agent Skills для разработки с помощью [Gas City](https://github.com/gastownhall/gascity). Цель — обсуждать требования с агентом, создавать по ним задачи и запускать их исполнение по формуле, не запоминая команды `gc`. Первый пользовательский клиент — OpenCode.

В [`packs/omg/`](packs/omg/pack.toml) находятся городской агент-оркестратор и скиллы для согласования, сохранения и поиска требований фичи в `docs/requirements/` выбранного rig, а также для отдельно подтверждённой декомпозиции в эпик и исходные подзадачи Beads. Сохранение требований не создаёт задач; декомпозиция не запускает их. По отдельному разрешению доступны проверочная формула v2 [`omg-probe`](packs/omg/formulas/omg-probe.toml) для типа `omg-probe` и формула [`omg-development`](packs/omg/formulas/omg-development.toml) для типа `omg-development`: подготовка worktree, план, реализация с тестами, документация, ограниченный review/fix loop и один шаг публикации напрямую в `origin/main` с подтверждённым закрытием исходного bead. Операционные результаты шагов хранятся локально в `.omg/tasks/<source-id>/artifacts/` task worktree; Beads хранит состояние и ссылки, а `docs/` — долговечную документацию. При сдвиге `main` или ошибке push задача остаётся открытой. Формул исследования и исправления бага пока нет. [Контракты pack](docs/pack-contracts.md), [общая идея](docs/project-vision.md), [согласованные сценарии](docs/workflow-requirements.md) и [архитектура скиллов](docs/skill-architecture.md) описывают границы работы; правила разработки — в [AGENTS.md](AGENTS.md). План разработки ведётся отдельно в Obsidian: `B - работа Plums Lab/OMG/roadmap.md`.
