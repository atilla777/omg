# Скиллы и интерфейс OMG

Этот документ определяет согласованные границы будущих скиллов и способы обращения к ним. Сценарии, артефакты и этапы исполнения приведены в [требованиях к workflow](workflow-requirements.md). Указанные скиллы и slash-команды ещё не реализованы.

## Пользовательский уровень

| Скилл | Ответственность |
| --- | --- |
| `omg-orchestrator` | Единый разговорный интерфейс. Выясняет намерение и текущий этап, находит сохранённые требования и задачи при возобновлении диалога, выбирает специализированный скилл. Не загружает весь справочник команд `gc` для обсуждения требований. |
| `omg-requirements` | Обсуждает требования и оформляет их в Markdown в `docs/` проекта. Не декомпозирует работу и не запускает выполнение. |
| `omg-decompose` | Из согласованных требований создаёт эпик и подзадачи Beads с критериями, связями и зависимостями. Не запускает их; для взаимодействия с CLI может обращаться к `omg-gc`. |
| `omg-gc` | Специализированная работа с CLI Gas City: обнаружение или создание city, подключение rig, проверка конфигурации и доступных формул, создание и маршрутизация работы, запуск согласованного выполнения, наблюдение и диагностика. Используется только при необходимости операций Gas City. |

`omg-orchestrator` может в одном диалоге вызвать `omg-requirements`, затем `omg-decompose`, а после явного запроса пользователя — `omg-gc` для запуска. В отдельных диалогах скиллы должны восстанавливать контекст по сохранённым требованиям и ID задач. Переход между этапами не должен трактоваться как автоматическое разрешение следующего этапа.

Первый клиент — OpenCode. Предусмотреть короткие команды `/omg` (универсальный диалог), `/omg-req` (требования), `/omg-dec` (декомпозиция); отдельный явный вход для запуска, например `/omg-start`, определяется вместе с реализацией запуска. Пользователь может обращаться к агенту и обычным текстом. Команды клиента — тонкие адаптеры к скиллам, не копии их процедур; [команды OpenCode](https://opencode.ai/docs/commands/) и pack-команды `gc` — разные интерфейсы. Область установки slash-команд (глобально либо в проектах) ещё не выбрана.

## Скиллы шагов формулы

Состав процедур выполнения определяется отдельными задачами OMG: кандидаты — техническое планирование, реализация с тестами, актуализация документации, ревью, прямое слияние в `main`. Формула определяет порядок и зависимости шагов, назначает исполнителя и указывает методику, например конкретный скилл ревью. Промпт агента определяет постоянную ответственность роли. Подробная методика шага находится **только в выбранном скилле**, без дублирования в промпте или формуле.

Для альтернативных методик допустимы разные скиллы (`omg-review-basic`, `omg-review-deep`), если они соблюдают один и тот же контракт входов, выходного артефакта и вердикта. Для выбора методики недостаточно наличия скилла в окружении: задание шага должно назвать её явно, а результат нужно проверить. Не стоит создавать отдельный скилл для полностью детерминированного действия только ради соответствия числу шагов формулы.

## Готовые материалы Gas City

Официальный [скилл `mayor` пакета `gascity`](https://github.com/gastownhall/gascity-packs/blob/main/gascity/skills/mayor/SKILL.md) покрывает разговор о требованиях, планирование, создание beads и запуск формул и полезен как референс. Его соглашения (`plans/<slug>/`, общий технический implementation plan до декомпозиции и `convoys[]` вместо `epics[]` в скрипте создания задач) расходятся с выбранной моделью OMG. Он не объявляется автоматически зависимостью `omg-gc` или остальных скиллов: решение об использовании его частей требует отдельной оценки и согласования.

Gas City предоставляет каталог скиллов из пакетов и ролей; при использовании с OpenCode нужно проверить видимость и фактическую загрузку нужных скиллов агентом. Взаимное упоминание скиллов само по себе не обеспечивает автоматический вызов. Внешний пакет и версию следует фиксировать только после проверки совместимости его контракта с OMG.

См. [правила размещения скиллов Gas City](https://github.com/gastownhall/gascity/blob/main/docs/guides/capabilities-for-coding-agent-users.md#skills) и [механизм скиллов OpenCode](https://opencode.ai/docs/skills/).
